    General

    Only superadmins can change these global limits.
    On: image uploads are saved as Base64 in the chat JSON. Off: images stay in uploads/ and are encoded again only when sent to the model.
    On: audio uploads are saved as Base64 in the chat JSON. Off: audio stays in uploads/ and is encoded again only when sent to the model.
    Absolute server-side upload cap for normal attachments. Default: 50 MB. Voice dictation uses its own endpoint and is not affected.
    Maximum image size saved as Base64 in the chat JSON when inline image storage is enabled. Default: 8 MB. 0 disables image inlining by size.
    Maximum audio size saved as Base64 in the chat JSON when inline audio storage is enabled. Default: 15 MB. 0 disables audio inlining by size.
    Separate budget for web_search, web_read and image_generate. Default: 20 rounds. 0 = unlimited.
    Separate budget for code workspaces, documents, MCP and custom tools. Default: 200 rounds. 0 = unlimited. A round may contain several parallel tool calls.
    Controls how much completed agent activity is kept in chat history and JSON exports. Full can make the database and exports very large; live previews stay independently bounded.
    Approximate persisted-history limit when "Keep only the latest tokens" is selected. Uses about 4 characters per token. Live agent previews keep a larger transient tail of about 8000 tokens. Default stored tail: 1000 tokens.

    Agent context compaction

    Personal runtime settings for long agent runs. Compaction is independent of MCP artifact externalization and works with Code Workspace, documents, MCP and custom tools.
    Before each agent pass, llama.cpp uses its exact chat input-token count when available. Other APIs and older llama.cpp builds fall back to a UTF-8 payload bytes / 4 estimate. For llama.cpp, the effective trigger is also capped below the runtime n_ctx with output room reserved. Default: 100,000. 0 disables automatic compaction.
    Always preserve this many newest complete assistant → tool-result rounds without summarizing them. Default: 6. After a successful compaction, normal compaction waits for this many new complete tool rounds before becoming eligible again. The current user request and not-yet-consumed results are protected separately.
    Default: use the model currently running the agent. Alternatively choose any model from your model list. A smaller-context model is supported through chunked checkpoint folding. The same Compaction model is also used to semantically compact raw tool evidence before a periodic supervisor review, with a separate evidence-preservation prompt. llama.cpp can expose real prompt-processing progress in Agent activity.

    Agent supervisor

    Optional periodic review by a separate model during long tool-using runs. Before each review, the Compaction model above semantically condenses the complete raw tool executions with a dedicated evidence prompt. The supervisor then receives user/assistant text plus that evidence compact and injects its checkpoint into the working agent as a new internal user message.
    Runs a supervisor review after approximately this many completed individual tool calls; parallel calls each count once. 0 disables the supervisor. Reviews are incremental: after the first checkpoint, only that checkpoint plus the new run segment is sent.
    Choose the stronger model that should periodically audit the working agent. Raw tool arguments/results are first semantically compacted by the configured Compaction model using a separate evidence-preservation prompt; oversized evidence is chunked/folded instead of head/tail-truncated. The supervisor receives only that compact, not the raw tool transcript.
    Archive old root chats
    Only folderless chats in the root are moved. Chats already organized in any folder are left untouched.
